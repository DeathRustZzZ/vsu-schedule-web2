## 🔄 Цикл жизни команды меню

```
1. ИНИЦИАЛИЗАЦИЯ
   ├─ Пользователь отправляет /start или нажимает кнопку
   ├─ Telegram отправляет Message или CallbackQuery
   └─ teloxide парсит и передает в handler

2. МАРШРУТИЗАЦИЯ
   ├─ handle_message() / handle_callback()
   ├─ callback_router::route_callback()
   ├─ Парсинг callback_data
   └─ Определение типа (MenuCommand vs CallbackData)

3. ОБРАБОТКА
   ├─ MenuDispatcher::dispatch()
   ├─ Match по типу команды
   ├─ Вызов соответствующего handler'а
   └─ Логирование действия

4. ОТРИСОВКА
   ├─ Создание сообщения с текстом
   ├─ Вызов menu::*_keyboard()
   ├─ Построение InlineKeyboardMarkup
   └─ Добавление parse_mode (MarkdownV2)

5. ОТПРАВКА
   ├─ bot.send_message() или bot.edit_message_text()
   ├─ reply_markup(keyboard)
   ├─ Телеграм API обрабатывает
   └─ Пользователь видит обновленное меню

6. ОЖИДАНИЕ
   └─ Ожидание следующего действия пользователя
```

## 🎯 Типичный сценарий взаимодействия

```
1. Пользователь пишет боту: "/start"
   └─► handle_message() 
       └─► Проверка БД
           └─► Не зарегистрирован
               └─► main_menu_inline_keyboard()
                   └─► Отправляет главное меню

2. Пользователь нажимает "📝 Зарегистрироваться"
   └─► handle_callback()
       └─► callback_router::route_callback()
           └─► MenuCommand::Register
               └─► MenuDispatcher::dispatch()
                   └─► show_registration_menu()
                       └─► Отправляет меню регистрации

3. Пользователь заполняет регистрацию (факультет, форма, курс, группа)
   └─► registration::handlers::handle_*()
       └─► Сохранение в БД
           └─► Отправляет меню успеха

4. Пользователь нажимает "◀️ Назад"
   └─► handle_callback()
       └─► callback_router::route_callback()
           └─► MenuCommand::Back
               └─► MenuDispatcher::dispatch()
                   └─► show_main_menu()
                       └─► Отправляет главное меню
```
